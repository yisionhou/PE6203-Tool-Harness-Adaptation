# 成员 2 方法与实现说明（报告素材）

本项目第一版采用基于依赖关系的选择性工具知识修补。工具身份由服务名与源工具名组成，知识包括工具定义、使用卡片、参数约束、调用形状示例以及依赖这些卡片的工具清单规则。适应过程以 Early 知识为统一基线，根据目标环境的可观察工具目录比较新增、删除、路由、参数、说明与可选输出 Schema。工具变化沿显式依赖图传播，确定需要重新生成的知识块。

三个策略共用同一个确定性生成器。不更新策略保留初始包的完整字节；全量重写重新生成任务范围内所有工具定义、规则和示例；选择性修补仅重新生成发生变化的工具记录及受影响的知识块。未受影响记录和规则文字通过内容哈希验证保留。对于受到影响却没有生成配方的自由文本规则，系统报告待审核项并中止导出，而不是继续使用可能过时的规则。全局提示只保留固定、与具体工具无关的使用约束，其他自定义知识必须声明依赖。

模板生成的调用示例只用于展示 JSON 形状，包含占位值，不作为任务答案或已经成功执行的调用。每个非空示例均经过对应 Schema 校验；无法构造合法示例时显式省略并记录原因。依赖检查拒绝悬空和循环引用。工具改名按旧身份移除与新身份增加处理，不根据名称相似性自行假定语义等价。该方法处理结构化或已声明的信息变化，不具备自动推断未暴露行为变化或任意自然语言语义的能力。

初次实现使用成员 1 已保存的三版本工具观察，覆盖任务 28、144、156。更新器仅读取指定工具目录，不读取答案、执行轨迹或参考标签；目录观察的形成仍依赖成员 1 的官方快照与描述层处理，应在实验协议中说明。各目标版本分别由相同 Early 基线独立适应。产物与成员 1 的 JSON 接口兼容，并附带初始观察哈希、更新 ID、差异路径、依赖影响范围、保留哈希及实际更新时间。

本次构建中，全量重写在九组环境/任务条件上共重新生成 31 条工具记录和 40 个规则块，选择性修补分别重新生成 8 条和 13 个。单次本机构建累计记录的更新时间约为 0.155 秒和 0.110 秒，包含检测、生成与知识验证，不包含共享初始建库、磁盘操作、兼容包导出、任务推理或评分。该小规模单次测量不支持稳定加速比例的结论。更新过程没有使用模型，token 成本为零；同一更新产物供任务重复使用时，应按更新 ID 去重成本。

九组对应条件下，全量和选择性策略最终提供给模型的工具定义与使用规则完全相同。这说明在当前确定性模板覆盖的范围内，局部更新能够达到相同的知识状态；不说明其任务得分更高。现有子集中的变化主要为可选参数与说明变化，任务 156 的新增工具也不是问题的必需工具，因此还需预先选择更有区分度的正式任务和保留能力对照任务。

初次工程验证包括 82 项自动测试以及三策略、三版本、三任务的 27 个真实工具环境发现与知识加载检查，全部通过。随后交付前自验完成 27 次真实任务，v2 有效评分 25/27，评分修复后 85 项测试通过。分数、轨迹、用量和限制见 [交付前验证报告](member2-validation-report.md)。这仍是少量任务的一次验证，不替代正式重复实验。测试展示了受影响自由文本规则可能导致遗漏更新、完整模板再生成可能丢失额外人工措辞的风险，但这些是机制测试，不能替代课程要求的实际任务损伤案例。后续正式实验应保持模型、解码参数、任务集合与评委协议一致，分别评估能力恢复、保留、成本及真实失败原因。
