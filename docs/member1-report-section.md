# 运行环境与基准集成说明（成员 1 报告素材）

本项目采用 MCPEvol-Bench，基准代码固定在 `888c779a0fe735f612ca62bdd1fdd7c9e6bf8701`，保留原任务与参考标签，不进行模型微调。执行环境为 Windows、Python 3.12.14、Node.js 24.21.0 和 npm 11.19.0，工具通过 `@1mcp/agent` 0.39.6 接入。Python 与 Node 依赖使用锁定文件记录，模型通过火山方舟接口调用 `deepseek-v4-flash-ga-260731`。阶段一旧机器版本记录与本次环境存在差异，本节采用阶段四实际验证版本。

运行器复用基准 Agent，在其外围增加任务选择、环境启动、知识传入和证据保存。Early、Middle、Late 分别映射官方 original、iter3、iter5 快照，部署前验证文件哈希，并应用版本对应的描述变化。固定子集包含任务 28、144、156，分别涉及文件与待办状态、时区转换及时间计算。任务 156 所在环境包含新增工具，但问题本身不要求使用该工具，因而不能将该案例解释为强制工具迁移验证。

每次任务使用独立工作目录、初始文件与空任务登记。三策略批次在运行前读入全部工具知识并保存原始字节及 SHA-256；执行时仅将所提供的工具名称、参数、说明和使用规则传给模型，不根据实时目录自动刷新旧知识。三个策略共用模型及推理配置：temperature 0.2、最大完成 token 4096、最多 10 轮、请求超时 60 秒，并在获得工具结果后的最终正文回答处停止。日志包含任务与运行 ID、知识引用、实际服务快照、模型参数、工具调用及完整返回、最终回答、错误和用量。

阶段四实现了三策略批次入口和评分桥接。评分输入基于保存的轨迹生成，无需评分时再次启动工具服务；评分提示复用上游 rubric，使用固定评委配置及相同任务对应的维度排列。judge 使用完整的已保存工具返回，策略系统规则和参考答案不作为评分输入。缺少轨迹的基础设施失败与评分解析失败均被保留，不能视为零分或从统计中删除。每个任务在三个环境的 TF 均有效时，计算其平均值减去总体标准差，供后续总体 ECS 汇总使用。

由于成员 2 尚未交付正式更新方法，本阶段用明确标记的工具知识样例验证三个策略标签的接入，完成任务 156 的三策略、三版本共 9 次真实运行，均正常结束且运行条件审计通过。随后发出 9 次评分请求，8 次得到 TF、Grounding、PE 均为 10 的有效评分；Late/full_rewrite 样例的评分响应正文为空，服务记录的 8,192 个完成 token 全部用于推理，因此该项保留为评分失败，相关 ECS 不计算。任务执行与评分分别记录 37,447 和 44,847 token；样例不代表真实知识更新成本。

本阶段有 56 项自动测试通过，并完成工作目录迁移后三个版本的工具启动检查。由此可以确认“知识文件—任务执行—日志读取—评分输入—跨版本对齐”的工程接口可交接。以上单任务、单次评分及样例结果不能支持三种更新方法的优劣结论。后续需由成员 2 提供真实算法产物，成员 3 固定正式任务集合与评委协议、处理缺失评分，成员 5 再分析适应与能力保留效果。
